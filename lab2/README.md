# Лабораторная работа №2: веб-интерфейс «Генератор экзаменационных билетов»

Веб-приложение на Python (Flask + HTML/JS) для распределения экзаменационных билетов: читает студентов из Excel, билеты из Word и ведёт хронологический журнал результатов в Excel. Открывается в браузере на `http://127.0.0.1:5000`.

---

## 🚀 Возможности и соответствие ТЗ

1. **Входные данные:** `students.xlsx` (лист = группа, A — Фамилия, B — Имя, данные со 2-й строки) и `tickets.docx` (`Билет N` + нумерованные вопросы `N. текст`).
2. **Интерфейс:**
   - Первый список заполняется группами (листами `students.xlsx`).
   - Второй список («Фамилия Имя») заполняется при выборе группы.
   - Кнопка «Сгенерировать билет» неактивна, пока не выбраны группа и студент.
   - Результат («Ваш билет № N» и 3 вопроса) — модальное окно; **ESC** закрывает его, приложение готово к следующему студенту.
3. **Назначение билета:** повторный студент получает номер из своей **самой первой** записи (`Повтор = да`), новый — случайный билет 1..N (`Повтор = нет`).
4. **Журнал `results.xlsx`:** создаётся при первом запуске, строка дописывается сразу после генерации, старые строки не меняются.
5. **Отказоустойчивость:**
   - Нет `students.xlsx` / `tickets.docx` — понятное сообщение на странице, сервер не падает.
   - Пустая группа — список пуст, кнопка неактивна.
   - `results.xlsx` открыт в Excel — сообщение и кнопка «Повторить».
   - Билет с < 3 вопросами или нераспознанным заголовком пропускается и логируется.

## 🧱 Архитектура и SOLID

| Модуль | Ответственность | Принцип |
| :--- | :--- | :--- |
| `repositories.py` | Интерфейсы `StudentSource`, `TicketSource`, `ResultJournal` и их Excel/Word-реализации | **ISP** (три узких интерфейса), **DIP** |
| `ticket_service.py` | `TicketService` — только правило назначения билета; источники приходят через конструктор | **SRP**, **DIP** |
| `docx_parser.py`, `excel_reader.py`, `journal_manager.py` | Разбор/чтение/запись конкретных форматов | **SRP** |
| `web_app.py` | `create_app(service)` — только HTTP ↔ сервис, ошибки → понятные JSON-ответы | **SRP**, **DIP** |
| `templates/index.html` | Интерфейс в браузере | — |
| `main.py` | Composition root — собирает реализации и запускает сервер | **OCP** |
| `e2e/e2e_server.py` | `LockableJournal` — декоратор над журналом для теста блокировки файла | **OCP**, **LSP** (подставляется вместо `ExcelResultJournal`) |

Чтение `.docx` сделано на стандартной библиотеке (`docx_io.py`, `zipfile` + `ElementTree`) вместо `python-docx`: его зависимость `lxml` — нативная DLL, которую блокирует Windows Smart App Control.

## 📋 Формат таблицы `results.xlsx`

| Группа | Фамилия | Имя | Номер билета | Дата и время | Повтор |
| :---: | :---: | :---: | :---: | :---: | :---: |
| ИТ-21 | Иванов | Иван | 4 | 2026-09-23 22:36:40 | нет |
| ИТ-21 | Иванов | Иван | 4 | 2026-09-23 22:37:12 | да |

## 🛠️ Установка и запуск

```bash
cd lab2
pip install -r requirements.txt
python create_sample_data.py   # опционально: демо students.xlsx и tickets.docx
python main.py                 # откроется браузер на http://127.0.0.1:5000
```

## 🧪 Тесты

**Unit-тесты** (парсинг Word, студенты по группе, идемпотентность, блокировка файла, сервис на фейках):

```bash
python -m pytest -v test_lab2.py
```

**E2E-тесты Playwright** (реальный браузер Chromium, все 9 критериев приёмки ТЗ):

```bash
npm install
npx playwright install chromium
npx playwright test
```

Playwright сам поднимает два тестовых сервера (`e2e/e2e_server.py`) на временных файлах: обычный и без `students.xlsx`.
