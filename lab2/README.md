# Лабораторная работа №2: веб-генератор экзаменационных билетов

## Что это

Веб-приложение (Python + Flask), которое распределяет экзаменационные билеты:

- **вход:** `students.xlsx` — группы и студенты, `tickets.docx` — билеты с вопросами;
- **выход:** `results.xlsx` — хронологический журнал всех выдач, включая повторные.

Преподаватель выбирает в браузере группу и студента, нажимает «Сгенерировать билет» и видит окно «Ваш билет № N» с тремя вопросами. Студент, который уже получал билет, получает **тот же** номер (из своей первой записи), а в журнал добавляется новая строка с пометкой «Повтор = да».

Логика построена по **SOLID** и покрыта unit-тестами и **e2e-тестами Playwright** в реальном браузере.

## Установка и запуск

```powershell
git clone https://github.com/esofl/exam_ticket_generator.git
cd exam_ticket_generator\lab2
python -m pip install -r requirements.txt
python main.py
```

Браузер откроется сам на **http://127.0.0.1:5000**. Остановить сервер — `Ctrl+C` в терминале.

В папке уже лежат демо-файлы `students.xlsx` и `tickets.docx`. Пересоздать их:

```powershell
python create_sample_data.py
```

### Формат входных файлов

**`students.xlsx`** — один лист на группу, имя листа = имя группы. Строка 1 — заголовок, со строки 2: колонка A — Фамилия, колонка B — Имя.

**`tickets.docx`** — абзацы вида:

```text
Билет 1
1. Вопрос первый
2. Вопрос второй
3. Вопрос третий
Билет 2
...
```

Билет с меньше чем тремя вопросами или с нераспознанным заголовком пропускается и записывается в лог, остальные работают.

### Формат `results.xlsx`

| Группа | Фамилия | Имя | Номер билета | Дата и время | Повтор |
| :---: | :---: | :---: | :---: | :---: | :---: |
| ИТ-21 | Иванов | Иван | 4 | 2026-11-17 10:36:40 | нет |
| ИТ-21 | Иванов | Иван | 4 | 2026-11-17 10:37:12 | да |

Файл создаётся при первой генерации, строки только дописываются.

## Как пользоваться

1. В первом списке выберите группу (это листы `students.xlsx`).
2. Во втором списке появятся студенты группы в формате «Фамилия Имя».
3. Кнопка **«Сгенерировать билет»** активна, только когда выбраны и группа, и студент.
4. Нажмите её — откроется окно «Ваш билет № N» с тремя вопросами. Строка уже записана в `results.xlsx`.
5. **ESC** закрывает окно — можно выбирать следующего студента.

Ошибки показываются красной плашкой на странице, приложение не падает:

| Ситуация | Что видно |
| :--- | :--- |
| Нет `students.xlsx` или `tickets.docx` | сообщение «Файл … не найден. Положите файл рядом с приложением и обновите страницу» |
| Группа без студентов | второй список пуст, кнопка неактивна |
| `results.xlsx` открыт в Excel | сообщение «Файл открыт в другой программе…» и кнопка **«Повторить»** |

## Сценарий демонстрации на защите

1. `python main.py` → выбрать `ИТ-21` → `Иванов Иван` → «Сгенерировать билет» → окно с номером и тремя вопросами.
2. **ESC** → окно закрылось, страница на месте.
3. Снова «Сгенерировать билет» для того же студента → тот же номер и плашка «Повтор».
4. Открыть `results.xlsx` → две строки, вторая с «да»; время по возрастанию.
5. Выбрать `Пустая-Группа` → список студентов пуст, кнопка серая.
6. Открыть `results.xlsx` в Excel и сгенерировать билет → сообщение и «Повторить»; закрыть Excel → «Повторить» → билет выдан.
7. Запустить тесты (ниже).

## Тесты

### Unit-тесты (pytest)

```powershell
cd lab2
python -m pytest -v test_lab2.py
```

11 тестов: разбор билетов из Word (с пропуском некорректного билета), чтение групп и студентов, пустая группа, заголовки журнала, идемпотентность (повторный выбор → тот же билет), блокировка файла, бизнес-логика на фейках без Excel/Word.

### E2E-тесты (Playwright, реальный браузер Chromium)

```powershell
cd lab2
npm install
npx playwright install chromium
npx playwright test
```

8 сценариев — по критериям приёмки ТЗ: группы и студенты из листов, активность кнопки, пустая группа, окно с тремя вопросами и мгновенная запись в журнал, ESC, повтор с тем же номером и «да», заблокированный журнал с повтором, отсутствующий `students.xlsx`.

Playwright сам поднимает два тестовых сервера (`e2e/e2e_server.py`) на временных копиях данных — ваши `students.xlsx`/`results.xlsx` не трогаются.

## Архитектура и SOLID

```text
Браузер (templates/index.html)
   │ fetch JSON: /api/groups, /api/students, /api/tickets
   ▼
web_app.py  create_app(service)        — только HTTP ↔ сервис
   ▼
ticket_service.py  TicketService       — правило «первый билет / случайный»
   │ зависит от интерфейсов (repositories.py)
   ├── StudentSource  ← ExcelStudentSource  (excel_reader.py)
   ├── TicketSource   ← DocxTicketSource    (docx_parser.py, docx_io.py)
   └── ResultJournal  ← ExcelResultJournal  (journal_manager.py)
main.py — composition root
```

| Модуль | Ответственность | Принцип |
| :--- | :--- | :--- |
| `repositories.py` | Интерфейсы `StudentSource`, `TicketSource`, `ResultJournal` и их Excel/Word-реализации | **ISP**, **DIP** |
| `ticket_service.py` | `TicketService` — только правило назначения билета; источники приходят через конструктор | **SRP**, **DIP** |
| `docx_parser.py`, `excel_reader.py`, `journal_manager.py` | Разбор/чтение/запись конкретных форматов | **SRP** |
| `web_app.py` | HTTP-слой; ошибки → понятные JSON-ответы | **SRP**, **DIP** |
| `main.py` | Сборка реализаций и запуск сервера | **OCP** |
| `e2e/e2e_server.py` | `LockableJournal` — декоратор над журналом для теста блокировки | **OCP**, **LSP** |

`.docx` читается стандартной библиотекой (`docx_io.py`: `zipfile` + `ElementTree`) вместо `python-docx`: его зависимость `lxml` — нативная DLL, которую блокирует Windows Smart App Control.

## Частые проблемы

| Симптом | Решение |
| :--- | :--- |
| `ModuleNotFoundError: flask` | `python -m pip install -r requirements.txt` |
| Порт 5000 занят | закройте другой процесс на 5000 или поменяйте `PORT` в `main.py` |
| Браузер не открылся | откройте вручную http://127.0.0.1:5000 |
| `npx playwright test` пишет, что нет браузера | `npx playwright install chromium` |
| `DLL load failed … Политика управления приложениями` | это Smart App Control; в проекте нет нативных зависимостей — проверьте, что вы не ставили `python-docx`/`playwright` для Python в то же окружение и запускаете команды из этого README |
